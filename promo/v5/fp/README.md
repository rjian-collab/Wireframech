# WIREFRAMECH 鋼弦機兵：第一人稱「高機動戰鬥」鏡頭（promo v5 素材）

這是一段**玩家第一人稱視角**的實機錄影：畫面用的是遊戲本身的第一人稱鏡頭（設定裡的視角切換／V 鍵），HUD 也是遊戲本身的，包括左上自機資訊窗、跟著敵機的敵方血條、擊破卡片和比分。不是用宣傳用的自由鏡頭（`H.cam`）去模擬。

- 遊戲版本：`claude/modest-ramanujan-ob1zy7` 分支的 `index.html`（新版 HUD），以 `?promo=1` 模式執行
- 規格：1920×1080、60 fps、H.264，長 5.97 秒（358 格）
- 錄影方式：在無頭 Chromium（SwiftShader 軟體算圖）裡用固定時間步長一格一格推進遊戲，每格截圖，最後用 ffmpeg 編碼

## 誠實說明：哪些是實際操作，哪些是擺拍或輔助

**實際操作（玩家做得到的事）**
- 所有移動都是遊戲本身的物理和輸入：側跳、推進平移、跳躍、鋼索發射、W 收索、放索、開砲。腳本只做玩家會做的事，也就是改滑鼠視角（yaw／pitch）和按鍵。
- 鋼索用的是遊戲的瞄準射線，打到的是真的可勾物件（松樹）。
- 敵機的機槍、曳光線、槍口火花都是遊戲本身的系統（敵機也是跑和玩家同一套武器程式）。
- 砲彈、爆炸、擊破判定、擊破卡片、比分、HUD 全部是遊戲本身的。
- 錄影時有記錄玩家有沒有被機槍打中：**0 發命中**，所以「閃過」是真的閃過。

**擺拍／輔助（請剪輯和文案注意）**
1. **起始位置是擺的**：玩家和敵機的開場位置、玩家朝向都用 `H.place` 指定。敵機的位置特別挑在第二條鋼索擺盪路徑的正下方，「剛好越過頭頂」是靠事先把敵機放在那裡，不是即時追擊出來的。
2. **敵機血量是預設的**：敵機一開始就是 **1500/6000（25%）**，等於「之前已經吃了 3 發 57mm」，畫面上敵方血條本來就只剩一小段紅色。遊戲裡 57mm 直擊傷害是 1500，**滿血敵機不會一發擊破**。比分預設成 2:1、倒數 2:11，讓畫面看起來像比賽打到一半。
3. **敵機是腳本操控的 AI**：用 `?promo=1` 的 `__botCmd` 控制，敵機站著不動，瞄準「玩家 0.17–0.27 秒前的位置，再往玩家移動方向的反方向多偏 2.6–3.5 m」。概念和遊戲 AI 一樣（遊戲 AI 瞄的是你 1 秒前的位置），但這裡刻意讓子彈從旁邊擦過，畫面比較好看。
4. **玩家血量鎖在 4380**：只是 HUD 數字，用來表示前面受過傷。實際上沒有被打中。
5. **擊破後的處理**：遊戲在擊破的瞬間會把敵機直接傳送回它的基地重生，平常就是「在爆炸裡消失」。腳本把重生後的敵機模型藏起來，避免遠處突然冒出一台；另外在擊破點多加兩次 `__promoBurst` 火花（宣傳模式才有的特效），爆炸看起來比一般遊玩更大。
6. **變速（0.25 倍）是錄影腳本調慢遊戲時鐘**，玩家實際玩的時候不會變慢；hit-stop、推近、震動是後製。

## 已知問題

- **曳光線很細**：遊戲的曳光彈是 1 像素的線，在 1080p 看得到，但壓縮後或縮小看會變淡。最明顯的是 0.3–1.7 秒和 2.9 秒左右的長條斜線。如果需要更明顯，建議剪輯時在曳光線上加一點光暈（請標成後製）。
- 從上方看下去時，敵機位在 HUD 中央準星圈底下，而且距離大約 17 m，在畫面中偏小。命中那一刻的推近（9%）有幫一點忙。
- 敵機緊貼一顆白色巨石站著，在第一段平視畫面裡，機體顏色和巨石有點混在一起。
- 「擊破 AI！」這則提示是遊戲寫死的文字（打 AI 模式），沒有顯示對手名字；左側的擊破卡片則有顯示名字。
- 長度 5.97 秒，比目標 6–9 秒稍短。如果需要更長，可以在剪輯時把開頭閃避段前面接一個 3 秒以內的建立鏡頭；或者用 `post_fp.py --hold` 加長 hit-stop。
- 物理模擬的步長是 1/120 秒，變速時有些格只有畫面插值、沒有推進物理，看起來還算順，不過逐格看會發現少數格幾乎重複。
- 每次重錄的結果可能會差 1–2 格（例如開砲在第 232 格還是第 244 格），因為 AI 的散布和畫面插值有些許不確定性。後製腳本會自動從 `probe.json` 抓出命中的那一格。

## 9:16 直式裁切計畫

- 從畫面正中央裁出 608×1080，再放大到 1080×1920（測試檔：`fp_highmobility_9x16_test.mp4`）。
- 敵機、準星、鋼索、爆炸幾乎都在畫面中央，裁切後都還在。
- **會被裁掉的東西**：左上自機資訊窗、擊破卡片、上方比分條、右上按鈕。如果要保留，可以：(a) 把左上 HUD（大約 x 30–260、y 10–160）另外疊回直式畫面的上方；或 (b) 前半段（0–2.4 秒）把裁切框往左移大約 150 px，讓敵機和曳光線多留一點空間。
- 字幕在直式版本要放在畫面高度大約 60–70% 的位置，避開 Reels／Shorts 底部 20% 的按鈕區。

## 如何重新錄製

需要 Node 和 Playwright（`require('playwright')`，不用跑 `playwright install`）、Python 3 和 Pillow、ffmpeg。

```bash
# 1) 取得遊戲檔（請不要動 /home/user/Wireframech）
git -C <你的 clone> fetch origin claude/modest-ramanujan-ob1zy7
mkdir -p <game>/assets && git -C <clone> show FETCH_HEAD:index.html > <game>/index.html
for f in assets/ground.jpg assets/mech.glb assets/pine.glb; do git -C <clone> show FETCH_HEAD:$f > <game>/$f; done
# CDN（three.js／rapier）會在第一次執行時用 curl 下載到 CDN_CACHE，之後從快取讀取；遊戲檔用攔截請求的方式提供，不需要開本機伺服器

# 2) 逐格錄影（1920×1080，每格都截圖，大約 15 分鐘）
GAMEDIR=<game> CDN_CACHE=<cache> node cap_fp.js choreo_fp.js <frames_dir> 1

# 3) 後製（hit-stop＋推近＋震動；--caption 加字幕；--vertical 輸出 9:16）
python3 post_fp.py <frames_dir> fp_highmobility.mp4 --end 350 --hold 8
python3 post_fp.py <frames_dir> fp_highmobility_caption.mp4 --end 350 --hold 8 --caption

# 調整動作時先「乾跑」（不算圖，只輸出位置、鋼索、開砲、擊破的時間點），一次可以比較好幾組參數：
VARS='[{"E":[268,-10]},{"E":[268.5,-9]}]' LAB=lab_fp.js node cap_fp.js base.js x
```

### 腳本說明

| 檔案 | 用途 |
|---|---|
| `cap_fp.js` | 錄影主程式：攔截請求提供檔案、假時鐘與逐格推進、亂數種子固定、截圖，並輸出 `probe.json`（每格的位置和事件） |
| `base.js` | 共用設定：PC 模式、繁中介面、隱藏開場 VS 畫面和滑鼠鎖定提示 |
| `h_init.js` | 宣傳片輔助 `H`（從 `promo-assets` 分支 `promo/v45/gen.py` 原樣複製） |
| `fp_helpers.js` | 第一人稱用的輔助函式：滑鼠視角平滑轉動、按鍵、敵機延遲瞄準、記錄 |
| `choreo_fp.js` | **分鏡腳本**。可調參數放在 `CFG`：敵機位置 `E`、兩個鋼索勾點 `A1`／`A2`、開始變速的距離 `dhSlow`、開火的距離 `dhFire` 等。也可以用環境變數 `CFG='{...}'` 覆寫 |
| `lab_fp.js` | 乾跑多組參數 |
| `post_fp.py` | 後製與編碼 |
| `sheet_fp.py` | 產生關鍵格縮圖表 |
