## 名詞小辭典（第一次出現時也會在括號裡說明）

| 名詞 | 白話解釋 |
|---|---|
| 景別 | 畫面拍多大的範圍。由大到小：大遠景（EWS）、遠景（WS）、全景（FS，主體整個入鏡）、中景（MS，主體約一半）、近景（MCU）、特寫（CU）、大特寫（ECU） |
| 機位 | 攝影機放在哪裡、從什麼高度和角度拍。仰角（low angle）是從下往上拍，讓主體顯得巨大；俯角（high angle）是從上往下拍；平視（eye level）；斜角（dutch，把畫面歪一邊） |
| 運鏡 | 攝影機怎麼動。固定（static）；搖鏡（pan，左右轉頭）；俯仰（tilt，上下轉頭）；推軌（dolly in／out，整台攝影機往前或往後移）；橫移（truck，左右平移）；環繞（orbit，繞著主體轉）；跟拍（follow／tracking）；變焦（zoom，鏡頭不動，只改變視角大小）；急推（crash zoom，非常快的變焦） |
| FOV／焦段感 | 視角大小。three.js 的 `fov` 是**垂直視角**。數字越小越像長鏡頭（望遠，背景被壓縮、主體顯大），數字越大越像廣角（空間感、速度感強）。本文會附上 35mm 等效焦段，方便對照電影習慣：FOV 70≈17mm、62≈20mm、50≈26mm、45≈29mm、40≈33mm、36≈37mm、30≈45mm、24≈56mm、17≈80mm、7.5≈183mm |
| 軸線／180° 原則 | 兩個角色之間畫一條假想線，攝影機一直留在線的同一邊，這樣 A 永遠在左、B 永遠在右。攝影機跳到線的另一邊，就叫「越軸」，觀眾會覺得兩個人突然換了位置 |
| 畫面方向（screen direction） | 角色面向或移動的方向（往左或往右）。剪接之間要保持一致 |
| 30° 原則 | 同一個主體連續兩個鏡頭，機位角度至少要差 30°，或者景別要明顯不同，否則看起來像畫面「跳了一下」（jump cut，跳接） |
| 動作剪接（cut on action） | 在動作進行到一半時換鏡，讓動作在下一個鏡頭接著完成，觀眾比較不會察覺換鏡 |
| 匹配剪接（match cut） | 用相似的形狀、顏色或動作，把兩個鏡頭接在一起 |
| hit-stop（命中停頓） | 命中的那一刻讓畫面停住幾格，增加打擊感 |
| punch-in（打擊推進） | 命中時畫面瞬間放大幾個百分比 |
| speed ramp（變速） | 同一個鏡頭裡，速度從正常變慢（或變快）再變回來 |
| 前導空間（lead room） | 主體面向或移動的那一側要多留空間，不能讓它「撞牆」 |
| 建立鏡頭（establishing shot） | 交代空間和地理位置的大遠景，讓觀眾知道「人在哪裡」 |
| 機內鏡頭 vs 自由鏡頭 | 機內鏡頭是玩家實際玩的時候看到的視角（第三人稱、HUD）；自由鏡頭是只有宣傳片才拍得到的攝影機（`H.cam`） |

## 1. 總評

v4 的**素材角度選得不差**。雷射爬上機體、57mm 從廣角急推到 183mm 望遠的預判射擊、三色塗裝的長鏡頭並排，都是好鏡頭。但整體的運鏡語言有三個根本問題：

1. **幾乎全部是固定鏡頭**。逐格動態分析顯示，15 個段落裡有 12 段的畫面位移接近 0（每格中位數 < 0.3 px，縮放 < 7%）。真正在動的只有 w02（數位推進）、w04（急推）、w05（跟拍）三段。主打的「螳螂鐮」四個鏡頭（w02、w06、w07、w09）全部是固定機位。對一支機甲動作片來說，能量太平。
2. **軸線亂跳**。英雄（藍機）在畫面中的方向是：w03 面向左 → w06、w07 面向右、在左邊 → **w08 跑到右邊** → w09 又回到左邊。w02 一個鏡頭裡面還直接越軸一次。觀眾會搞不清楚誰在打誰。
3. **沒有建立空間，也沒有「這就是遊戲畫面」的證據**。唯一的浮空島大遠景（w01）被雜訊和 VS 卡片蓋住。實際遊玩視角（第三人稱＋HUD）只有 n09 一段 2.3 秒，佔全片 6%。慢動作則用在 5 個動作段落，近戰鏡頭**沒有一個是以正常速度呈現的**，所以觀眾看不到「實際玩起來有多快」。

v5 分鏡在「講什麼」上已經修正很多。本文把重點放在「**怎麼拍**」：統一軸線（英雄一律在左邊、面向右），景別要大小交替，每一個運鏡都要有動機，打擊點固定用「停頓 → 推進 → 震動」三連拍，並且至少放 3 個機內視角的鏡頭。

## 3. 主要問題排序（附畫面證據）

證據圖都在 `camera-frames/`。

### P1 🔴 軸線（180° 原則）全片跳了 4 次
- **鏡頭內越軸（w02，3.0→3.4 秒）**：`gen2.py` B2 在 `ml.ph===2` 那一格把機位從 (146,5.4,-43.4)（+z 側，英雄背後）直接換到 (154.2,3,-50.4)（−z 側）。前一格英雄在左、對手在右，下一格整個反過來。→ `E1_axis_jump_w02_t3.0_vs_t3.4.jpg`
- **w03 對 w06**：L3 的機位在 −z 側，英雄面向左；S5 的機位在 +z 側，英雄面向右。→ `E3_axis_w03_t6.8_vs_w06_t15.0.jpg`
- **w07 → w08（最嚴重，而且剛好在 drop）**：S6 的機位在 z=−34.5（+z 側），藍機在左；S7 的機位在 z=−64（−z 側），藍機在右。→ `E2_axis_flip_w07_t17.0_vs_w08_t20.0.jpg`
- **w08 → w09**：又翻回來。
- **修法**：v5 全片統一規定**「攝影機在 +z 側（z > −46），藍機在畫面左邊、面向右；黃機在右邊、面向左」**。既有素材要換邊時，把 `H.cam` 的 z 鏡射成 `z' = −92 − z`，看向點的 z 也一樣處理；`botAim` 等 z 方向的偏移量要反號。只有正背後的追逐鏡頭或正面的鏡頭可以用來「合法越軸」，而且一次只能越一次。

### P2 🔴 主打的近戰鏡頭全部是固定鏡頭，而且看不清楚
- w06、w07、w09 都是平視、固定或幾乎固定的側面中景（實測縮放 1.00–1.04）。→ `E8_static_medium_w06_t15.0_w08_t20.0_w09_t26.5.jpg`
- w09 拼刀用純側面拍，兩台蜘蛛腳機體在同一個深度上重疊，刀刃交叉的那一刻被腳擋住，還加了 0.9 的白閃。→ `E5_parry_clutter_t25.95_t26.5_t27.8.jpg`
- w02 是 8 倍慢動作的大特寫，觀眾只看到一根管子和一條橘線。→ `E9_blade_ecu_t5.0.jpg`
- **修法**：近戰鏡頭改用 **3/4 斜側、低機位（攝影機在機體中心以下 0.5–0.9 m）**，讓兩台機體在深度上錯開，刀刃交叉的位置剛好落在天空背景前（剪影最清楚）。命中時固定用「停頓 → 推進 → 震動」三連拍（參數見第 7 節）。

### P3 🔴 擺盪（雙鋼索）拍不出速度和弧線
- 鏡頭被鎖在機體上（偏移量固定），所以機體永遠在畫面中央，擺盪的弧線變成背景在動。距離約 27 m，機體只佔畫面高度約 1/6。頂點用 0.3 倍慢動作 33 格，實測最後 2.3 秒畫面幾乎靜止。→ `E4_swing_small_centered_t11.2_t12.5_t13.6.jpg`
- **修法**：分成三段：① 廣角仰拍交代兩條鋼索和兩個錨點 → ② **有延遲的跟拍**（攝影機追得比機體慢，讓機體先衝出畫面中心再被追上；這是 Insomniac 在 Spider-Man 用的「expressive camera」概念，見第 4 節）→ ③ 頂點 0.5 倍慢動作 8 格，加 30° 環繞。距離縮到 8–10 m。

### P4 🔴 沒有交代空間（浮空島）
- w01 是唯一的大遠景，卻被雜訊和 VS 卡蓋住（`E7_establishing_missing_t0.45_t1.5.jpg`）。w08 遠景是平視地面高度，背景是一整排樹牆。
- **修法**：v5 #04 的 VS 鏡頭要負責「建立空間」：機位降到 45 m 高，讓地平線、天空和遠方的島入鏡，VS 卡縮小放到下三分之一。#07 和 #20 的擺盪鏡頭用仰角，把天空和遠方的島當背景。

### P5 🟠 慢動作用太多，沒有「實際速度」的參照
- 5 段動作有慢動作，近戰 4 段全部是慢動作。慢動作要有對比才有力量：前後都是正常速度，命中那一下才變慢。
- **修法**：v5 每一個近戰鏡頭都用 **speed ramp（變速）**：正常速度 → 接觸前 3 格降到 0.25–0.35 倍 → 維持 6–8 格 → 4 格內回到正常速度。#10 和 #12 的突進段落維持正常速度。

### P6 🟠 景別單調、沒有大小交替
- 後半段連續 4 個中景；w02 大特寫直接接 w03 近景，兩個都很緊，觀眾沒有喘息和對照。
- **修法**：v5 照「緊 → 鬆 → 緊」交替（見第 6 節的景別欄）。

### P7 🟠 機內視角太少，賣不出「玩起來就是這樣」
- 只有 n09 一段 2.3 秒。而且 P1 是用 `H.cam` **模擬**機內鏡頭，不是遊戲真正的鏡頭。
- **修法**：#08（放開鋼索衝向對手）、#15（PC）用真正的遊戲鏡頭（`H.free()`）加 HUD；#06 保留越肩視角和瞄準預判標記，作為「半機內」鏡頭。機內視角目標佔動作段落的 25% 以上。

### P8 🟡 同一鏡頭內的跳接
- w09b 用瞬移加白閃；n13 的數位放大從 2.1 跳到 1.15。這兩個都是「沒換機位卻跳了一下」。
- **修法**：要換就乾脆剪掉、從新的機位開始（#11 從 S8 第 36 格開始拍）；數位放大用一條連續的曲線。

### 做得好、應該保留的地方
- w04 的「急推跟著預判點」是全片唯一運鏡和遊戲機制完全綁在一起的鏡頭，v5 #06 照用。（`E6_good_crashzoom_w04_t8.3_t9.0.jpg`）
- w03 雷射段的「慢慢逼近」推鏡（FOV 40→32），有威脅感的動機。
- w11 用長鏡頭並排三色塗裝，構圖清楚。
- w07 的停頓加震動，力道對了，只是機位不對。

## 7. 給 `?promo=1` 攝影機腳本的具體參數

下面是可以直接放進 `gen5.py` 的 `per` 字串的寫法。座標系和 v4 相同：英雄 L 在 (150, 2.2, −46)，`yaw = −π/2` 時面向 +x；對手 B 在 +x 方向。`p = H.p()`、`q = H.q()`、`mx = (p.x + q.x) / 2`。新增兩個工具函式：

```js
// 在 INIT 的 H 裡新增
H.lag = (k) => { // 延遲跟拍：攝影機位置每格往目標靠近 k（0.12–0.2）
  return (tx, ty, tz) => { const c = H._c || (H._c = {x: tx, y: ty, z: tz});
    c.x += (tx - c.x) * k; c.y += (ty - c.y) * k; c.z += (tz - c.z) * k; return c; };
};
H.ramp = (c, a, lo, hold, out) => { // 變速：c = 相對接觸格的格數
  if (c < -a) return 1; if (c < 0) return H.lerp(1, lo, (c + a) / a);
  if (c < hold) return lo; if (c < hold + out) return H.lerp(lo, 1, (c - hold) / out); return 1; };
```

後製（`build5.py`）的打擊三連拍，沿用 `zoom()` 和 `shake()`：

```python
def impact(im, k, hit, stop=6, push=0.10, amp=12, cx=W/2, cy=H/2):
    # k = 畫格；hit = 命中格。停頓本身由序列重複 hit 格來做（同 v4 sc_aim 的 [imp]*9）
    if hit <= k < hit + stop + 8:
        im = zoom(im, 1 + push * ease((k - hit + 1) / 3), cx=cx, cy=cy)
    return shake(im, k, hit + stop, amp)   # 停頓結束後才震動，8 格遞減
```

## 8. 9:16 直式版運鏡筆記（重點鏡頭）

原則：three.js 的 FOV 是垂直視角。直式畫面變得「高而窄」，同樣的 FOV 左右會少拍很多。**兩機橫向排開的鏡頭在直式裡一定會被切掉**，所以要把「左右關係」改成「前後、上下關係」，同時保持英雄在下方或左下、對手在上方或右上，這是直式版的「軸線」。

| # | 直式做法 |
|---|---|
| 01 | 攝影機升高到 `p.y+3.5`，俯角 25°，從英雄左後方拍。英雄在畫面下半、對手在上半，刀刃交叉點在畫面高度 45% 的位置。FOV 55 |
| 02 | 從英雄背後越肩拍，對手在上三分之一；蓋章字放在畫面高度 18–28% 的位置 |
| 06 | 很適合直式：急推目標原本就在天空，把 FOV 42 改成 60 起推，最後一樣推到 7.5 |
| 07 | **最適合直式**：鐘擺是垂直運動。用仰角看兩條鋼索往上延伸到畫面頂端，FOV 70，機體在下三分之一 |
| 09 | 刀刃由下往上展開，仰角拍；英雄佔中間 60% 高度 |
| 11 | 改用斜上方 30° 俯拍，兩機前後排開，拼刀點在畫面中央；擊退時一台往上、一台往下 |
| 12 | 正後方跟拍突進，對手在上方，命中時推進 12% |
| 15 | 直式版建議拿掉（或改成手機直式實際操作的錄影，順便證明可以用手機玩） |
| 20 | 機體從畫面下方擺上來，在頂點轉向鏡頭開砲 |
| 21 | Logo、網址、QR 上下排列；背景用長鏡頭的機體剪影 |

如果沿用橫式素材（裁切或模糊延伸版型），請確定主體在畫面中間 1080 px 寬的範圍內。#01、#11 這種左右排開的兩機鏡頭一定會切到人，**請重新用直式拍**。
