# WIREFRAMECH 鋼弦機兵：第三人稱「高機動戰鬥」鏡頭（promo v5 素材）

這是一段**玩家第三人稱視角**的實機錄影。畫面用的是遊戲本身的第三人稱追尾鏡頭，也就是玩家在「設定 → 鏡頭 → 第三人稱」打開（電腦版按 V 切換）時看到的畫面：鏡頭在機體後上方 15 m，視線方向就是準星方向。HUD 也是遊戲本身的，包括左上自機資訊窗、跟著敵機的名字和血條、中央準星和高度／速度刻度，還有右上的擊破卡片和比分。**沒有**用宣傳用的自由鏡頭（`__camOverride`／`H.cam`），也**沒有**用鏡頭俯仰輔助。

- 遊戲版本：`claude/modest-ramanujan-ob1zy7` 分支的 `index.html`，commit **ff65981**（擊破卡片在右上、單排；右上只有設定齒輪；觸控按鈕縮小版）。以 `?promo=1` 模式執行
- 規格：1920×1080、60 fps、H.264（CRF 24），長 **6.38 秒**（383 格）
- 錄影方式：在無頭 Chromium（SwiftShader 軟體算圖）裡用固定時間步長一格一格推進遊戲，每格截圖，最後用 ffmpeg 編碼

## 和第一人稱版（`/home/user/promo_v5_fp/`）的差別

1. **鏡頭**：改成遊戲的第三人稱追尾鏡頭（`setView(true)`，和設定裡的開關、V 鍵是同一個函式）。自機一直在畫面中下方，鏡頭自然跟在後面，擺盪的速度感來自背景掠過。
2. **瞄準**：第三人稱下準星是鏡頭中心的射線，不是機體眼睛的方向。腳本照遊戲的鏡頭公式（`CONFIG.tp`：後退 15 m、高 5.5 m）和 `aim3P` 反推「滑鼠要轉到哪裡，準星才會落在目標上」，再像玩家一樣平滑轉過去。
3. **開火角度**：第一人稱版是在敵機正上方（約 −80°）往下打。第三人稱如果往正下方看，鏡頭會從自機正上方往下拍，**自機會整個擋住敵機和命中點**（已實測）。所以改成在斜上方約 50° 開火，再從火球上方飛過。「越頂」的畫面改由開火前那一段來呈現（自機在上、敵機在下）。
4. **敵機位置**：從 (268, −10) 移到 (261, 2)。這樣越頂的時候敵機剛好在自機前下方，開場閃避時敵機也不會被巨石擋住（已檢查整段 0–2.37 秒的視線都沒被擋）。
5. **遊戲版本**：換成最新的 ff65981。擊破卡片在右上、單排，沒有「擊破 AI！」提示。
6. **曳光彈光暈**（後製，見下方）。
7. **9:16 版**有重新構圖，HUD 也重新排過。

## 誠實說明：哪些是實際操作，哪些是擺拍或後製

**實際操作（玩家做得到的事）**
- 所有移動都是遊戲本身的物理和輸入：側跳、推進平移、跳躍、鋼索發射、W 收索、放索、開砲。腳本只做玩家會做的事，也就是改滑鼠視角（yaw／pitch）和按鍵。
- 鏡頭是遊戲的第三人稱鏡頭，HUD 全部是遊戲本身的。
- 鋼索用的是遊戲的瞄準射線，打到的是真的可勾物件（松樹）。
- 敵機的機槍、曳光線、槍口火花都是遊戲本身的系統（敵機也是跑和玩家同一套武器程式）。
- 砲彈、爆炸、擊破判定、擊破卡片、比分都是遊戲本身的。
- 錄影時有記錄玩家有沒有被機槍打中：**0 發命中**，所以「閃過」是真的閃過。

**擺拍／輔助（請剪輯和文案注意）**
1. **起始位置是擺的**：玩家和敵機的開場位置、玩家朝向都用 `H.place` 指定。敵機的位置是特別挑的，讓第二條鋼索擺上去時剛好越過它的前上方。
2. **敵機血量是預設的**：敵機一開始就是 **1500/6000（25%）**，等於「之前已經吃了 3 發 57mm」，所以畫面上的敵方血條一開始就只剩一小段紅色。遊戲裡 57mm 直擊傷害是 1500，**滿血敵機不會一發擊破**。比分預設成 2:1、倒數 2:11，讓畫面看起來像比賽打到一半。
3. **敵機是腳本操控的 AI**：用 `?promo=1` 的 `__botCmd` 控制，敵機站著不動，瞄準「玩家 0.17–0.27 秒前的位置，再往玩家移動方向的反方向多偏 2.6–3.5 m」。概念和遊戲 AI 一樣（遊戲 AI 瞄的是你 1 秒前的位置），但這裡刻意讓子彈從旁邊擦過，畫面比較好看。
4. **玩家血量鎖在 4380**：只是 HUD 數字，用來表示前面受過傷。實際上沒有被打中。
5. **擊破後的處理**：遊戲在擊破的瞬間會把敵機直接傳送回它的基地重生，平常就是「在爆炸裡消失」。腳本把重生後的敵機模型藏起來，避免遠處突然冒出一台；另外在擊破點多加兩次 `__promoBurst` 火花（宣傳模式才有的特效），爆炸看起來比一般遊玩更大。
6. **變速（0.25 倍）是錄影腳本調慢遊戲時鐘**，玩家實際玩的時候不會變慢。
7. **鏡頭**：沒有用鏡頭俯仰輔助，也沒有改鏡頭距離。腳本每格會把遊戲的 `tpCam.pos` 設成「遊戲這一格本來就會算出的鏡頭位置」，讓不算圖的乾跑和正式錄影的瞄準結果一致；正式錄影時遊戲算圖後會再用自己算的值覆蓋。

**後製（`post_tp.py`，只在宣傳片裡）**
- hit-stop 8 格、推近 9%、震動、字幕。
- hit-stop 放在來源第 256 格。遊戲判定擊破是在第 255 格，256 格是命中閃光第一次清楚出現的那一格（變速中，只差約 1/240 秒的遊戲時間）。
- **曳光彈光暈**：遊戲的曳光彈是 1 像素的細線。錄影時記下每一格遊戲曳光線的螢幕座標（`probe.json` 的 `trc`），後製時沿著同一條線疊一層暖黃色光暈和 2 像素亮芯。光暈的位置、長度、淡出都跟著遊戲的曳光線走，只是比較粗、比較亮。**請標成後製效果。**
- 9:16 版的 HUD 重新排過（見下方）。

## 已知問題

- **自機大小**：開場地面段自機約佔畫面高度 22–30%。到了空中，鏡頭往下看，機體從上方看會變扁，大約只佔 15–20% 高（橫向約佔 30% 寬）。原因是遊戲的鏡頭距離固定在 15 m，這版不改鏡頭距離。如果一定要更大，只能在剪輯時數位放大，但 HUD 也會跟著放大。
- **命中閃光偏小**：開火時是在斜上方往下打，命中點剛好落在中央準星和自機背部附近，所以命中的閃光比第一人稱版小。紅色命中標記看得到；大火球大約 0.2 秒後才從自機下方冒出來（4.5 秒左右最明顯）。
- **開火前那幾格（3.93–4.12 秒）**敵機在準星正中央，被 HUD 準星圈和自機的砲管蓋住一部分。這是遊戲第三人稱 HUD 本來的樣子。
- 長度 6.38 秒。如果需要更長，可以用 `--hold` 加長 hit-stop，或在剪輯時往前接一個建立鏡頭。
- 物理模擬的步長是 1/120 秒，變速時有些格只有畫面插值、沒有推進物理，逐格看會發現少數格幾乎重複。
- 每次重錄的結果可能會差 1–2 格，後製腳本會自動從 `probe.json` 抓擊破的那一格（如果有用 `--impact` 指定就以指定的為準）。

## 如何重新錄製

需要 Node 和 Playwright（`require('playwright')`，不用跑 `playwright install`）、Python 3 和 Pillow、ffmpeg。不需要開本機伺服器，遊戲檔是用攔截請求的方式直接從硬碟讀取。

```bash
# 1) 取得遊戲檔（請不要動 /home/user/Wireframech）
git -C <你的 clone> fetch origin claude/modest-ramanujan-ob1zy7
mkdir -p <game>/assets && git -C <clone> show FETCH_HEAD:index.html > <game>/index.html
for f in assets/ground.jpg assets/mech.glb assets/pine.glb; do git -C <clone> show FETCH_HEAD:$f > <game>/$f; done
# CDN（three.js／rapier）第一次執行時會用 curl 下載到 CDN_CACHE，之後從快取讀取

# 2) 逐格錄影（1920×1080，每格都截圖，約 380 格，大約 16 分鐘）
GAMEDIR=<game> CDN_CACHE=<cache> node cap_tp.js choreo_tp.js <frames_dir> 1

# 3) 後製（hit-stop＋推近＋震動＋曳光光暈；--caption 加字幕；--vertical 輸出 9:16）
python3 post_tp.py <frames_dir> tp_highmobility.mp4 --end 375 --hold 8 --impact 256 --crf 24
python3 post_tp.py <frames_dir> tp_highmobility_caption.mp4 --end 375 --hold 8 --impact 256 --crf 24 --caption
python3 post_tp.py <frames_dir> tp_highmobility_9x16.mp4 --end 375 --hold 8 --impact 256 --crf 22 --caption --vertical
#   --no-glow 可以關掉曳光光暈

# 只截幾格來看構圖（KEYS＝要截的格號，第 4 個參數 1000＝其他格不截圖）：
KEYS=116,228,272 FRAMES=280 node cap_tp.js choreo_tp.js <dir> 1000

# 調整動作時先「乾跑」（不算圖，只輸出位置、鋼索、開砲、擊破的時間點和敵機視線 los），一次可以比較好幾組參數：
VARS='[{"E":[261,2]},{"E":[262,3.5]}]' LAB=lab_tp.js node cap_tp.js base.js x
```

## 近距離開砲的遊戲行為（照 64be093 的程式碼查過，沒有自己發明機制）

- **沒有最小射程**：`cannonTick` 沒有最小距離的判斷。
- **砲彈從哪裡出發**：從機體中心（眼睛高度）出發（程式註解 v3.9：「以前從前方 1.5m 出發，貼臉時砲彈直接出現在敵人身體裡、判定不到」）。`shellsTick` 的射線會排除自己的碰撞體，每一步大約 5.8 m，所以貼臉時第一步就會直擊敵機，不會出現「砲彈生在敵機碰撞體裡面」的問題。直擊 1500 剛好打掉敵機剩下的 1500 HP。
- **自己會不會被爆風炸到：不會。** 爆風只會檢查射擊方的敵人清單（`targets = a.enemies`），而 `actorDamage` 遇到 `curActor === v` 也會直接 return false（註解寫「不會打到自己」）。所以零距離開砲，遊戲本身就**不會**讓自機受爆風傷害。自機 HP 仍然鎖在 4380（只是 HUD 數字，表示之前受過傷）。這段實際上沒有任何傷害需要被鎖住，影片裡也沒有演出自機被爆風傷到。
- **後座力／爆風推力**：遊戲只有在**空中**開砲時會有後座力（往後 3 m/s），爆炸本身也**沒有**推力。這一版開砲時自機已經在地上，所以沒有後座力。看起來像「被炸飛」的後退，其實是玩家自己按 Space＋S 後跳，再加上推進。
- `aim3P` 在瞄準點離眼睛小於 2 m 時會回傳 null。這次瞄準點大約在 3 m，沒有碰到這個情況。

## 誠實說明（只列和 `_tp` 版不一樣的地方；其他同上）

**擺拍／輔助**
1. **鏡頭輔助約 0.42 秒（第 255–271 格，含 8 格 hit-stop 共 25 格）**：從落地到擊破後 4 格這段，把遊戲的 `CONFIG.tp.dist` 從 15 m 改成 8 m。鏡頭方向、準星、`aim3P` 都沒變，只有鏡頭沿著同一條視線往前移。原因是在 15 m 的距離下，兩台機體都很小，敵機會被準星和鎖定框蓋住，「貼臉」的感覺出不來（已實測）。拉近和拉回各只用 3 格，**看得出來是一個推近的動作**，請標成宣傳用的鏡頭。
2. **敵機的動作是腳本操控的**：後退的路線（停在 (261.5, 15)）和起跳的時機都是腳本決定的，用的是遊戲本身的移動和跳躍指令。機槍一樣是「瞄玩家之前的位置再偏一點」。
3. 起始位置、敵機血量 1500/6000、比分 2:1，和 `_tp` 版一樣都是擺的。
4. 擊破後把重生的敵機模型藏起來（同 `_tp` 版）。`__promoBurst` 火花（宣傳模式才有的特效）在擊破、擊破後 3 格、回望前後各放一次，讓回望時還看得到火花。**遊戲本身沒有殘骸**，敵機在擊破的瞬間就被傳送回基地，所以回望看到的是逐漸淡掉的爆炸球和火花，不是殘骸。
5. **變速**：接觸前後是 0.25 倍，轉身時是 0.5 倍，回望停留時是 0.3 倍。火球在正常速度下只會持續 0.55 秒，靠變速才能撐到回望的時候還看得到。

**後製（`post_pb.py`）**：hit-stop 8 格、推近 12%、震動、字幕、曳光光暈。甩鏡的動態模糊是依每格的 yaw 變化做水平拖影（最長 110 px），**HUD 也會一起被模糊**，只有約 0.3 秒。9:16 版的重新構圖和 `_tp` 版相同。

## 已知問題

- **嚴格來說沒有真的「貼到」**：開火時兩台機體中心相距 4.9 m，機殼間約 2 m（自機砲管伸向敵機）。從追尾鏡頭看起來是疊在一起的，但如果逐格看，並不是物理上接觸。
- 準星、鎖定框和金色的鎖定火花會蓋住敵機的一部分，這是遊戲本身的 HUD。
- 鏡頭輔助的拉近和拉回各只有 3 格，看起來比較像跳切／推近。如果剪輯想要更順，可以把 `choreo_pb.js` 的 `camD` 調大，或延長拉近的格數（但要注意總長不能超過 0.5 秒）。
- 轉身那段（約 4.9–5.1 秒）只轉了約 138°，所以大火球還留在畫面邊緣。
- 第 264–265 格敵機模型還會畫一格（算圖比判定晚一格），爆炸從第 266 格開始。
